# jrs-hotfix 0.8.1

A security update of the JSON library jrs-hotfix bundles, and nothing else that changes how it
works. 0.8.0 carried Jackson 2.22.2, which has four high-severity advisories; 0.8.1 carries
2.22.3, which fixes them. Anyone on 0.8.0, or earlier, should use 0.8.1 instead. Download the
archive for your system below, check it against `SHA256SUMS`, and unpack it in place of the old
one. It includes its own Java; nothing needs to be installed. `README.md` inside the archive is
the manual; `jrs-hotfix --docs` prints it.

## What changed

- **Jackson 2.22.2 → 2.22.3** (#57): jackson-databind and jackson-core, which the release
  archives and `jrs-hotfix.jar` bundle. It fixes:

  | Advisory | Library | Problem |
  |---|---|---|
  | [GHSA-7hhh-6rmp-j9qf](https://github.com/advisories/GHSA-7hhh-6rmp-j9qf) | jackson-core | Unbounded memory growth while reporting an invalid token (denial of service) |
  | [GHSA-p6pp-m3f8-5c89](https://github.com/advisories/GHSA-p6pp-m3f8-5c89) | jackson-core | Quadratic backtracking on a crafted number (denial of service) |
  | [GHSA-cxp5-3px4-pw24](https://github.com/advisories/GHSA-cxp5-3px4-pw24) | jackson-databind | Quadratic forward-reference completion |
  | [GHSA-wv8q-qhhj-9h54](https://github.com/advisories/GHSA-wv8q-qhhj-9h54) | jackson-databind | Every unknown raw type id retained |

  How exposed 0.8.0 was: jrs-hotfix reads JSON only from its own home (`settings.json`, run
  records and plans, the undo record, baselines and merges) and from nothing a package, a WAR or
  the server sends it. Exploiting these needs a crafted file in the home, which only the account
  that runs jrs-hotfix can write, and the worst outcome is that jrs-hotfix hangs or runs out of
  memory, before or between the steps of a run. A run stopped that way is recovered as any
  interrupted run is, with `runs resume` or `runs undo`.
- **A security policy and a contributing guide** (#56). `SECURITY.md` says how to report a
  vulnerability privately, as a GitHub security advisory or by email, and that fixes go into the
  latest release only. `CONTRIBUTING.md` says how to report a bug and propose a change. Issues
  now go through a bug report or a feature request form.
- The README no longer says jrs-hotfix "records" hotfixes: `record` went in 0.6.0.

## What scripts must change

Nothing. The commands, options, messages, exit codes and the home's files are those of 0.8.0.

## Tested

`verify` green on Windows and Linux in CI with Jackson 2.22.3: the 645 unit tests and the 20
acceptance tests through the shaded jar, which read and write every JSON file the home holds.

## Known limitations

The limitations of 0.8.0 stand.
