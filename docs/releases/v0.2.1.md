# jrs-hotfix 0.2.1

Two fixes from the first day of 0.2.0 on servers other than the two it was tested on. Download
the archive for your system below, check it against `SHA256SUMS`, and unpack it; a home written
by 0.2.0 or 0.1.0 is read as it is.

## What changed

- `jrs-hotfix forget <id>` takes a hotfix out of the ledger because the webapp no longer holds
  it. The ledger lives in the home beside the installation, not in the webapp, so after a
  redeploy from a WAR it still lists the hotfixes the old webapp had, and preflight refuses the
  next apply: the webapp states an older build than the ledger's newest entry. 0.2.0 left no
  way out but editing `ledger.json` by hand, and said "already installed" in the same breath,
  which the webapp disproves. The refusal now names `forget`, and reports only what the build
  says. `forget` changes nothing on the server; the entry's snapshot stays until `runs prune`.
- The acceptance tests' stand-in Tomcat is a shell loop. On a machine whose `/bin/sh` is bash
  (Fedora, RHEL, Amazon Linux), bash execs a lone command, so the stand-in lost the marker the
  tests look for and every acceptance test failed at start-up; dash (Ubuntu, Debian) keeps the
  shell, which is why the tested machines never showed it. Test code only; the tool is
  unchanged by it.
